## 0. How to read this

- **One canonical id per distinct operator.** If two researchers described the same operator, or one described an implementation strategy of another, the strategy becomes a **variant id** under its parent (for example `gaussian-separable` under `gaussian-blur`). Variant ids stay stable, so the app can still expose them as presets or algorithm toggles. They are not counted as separate blurs.
- **Count.** The canonical catalog has **55 entries** in 11 families: **51 distinct blur operators**, plus `heat-equation` (the same operator as `gaussian-blur`, kept for the diffusion lesson) and **3 blur-derived effects** in F11 (`drop-shadow`, `bloom`, `god-rays`, which the brief's family list asks for). On top of these come **7 contrast entries** that are not blurs. There are **32 variant ids** on top of these. That is above the 35–50 target. The three researchers documented more genuinely distinct operators than 50, and cutting real distinctions (a cat's-eye PSF field is not a disc blur; a guided filter is not a bilateral) would weaken the "what makes each blur unique" requirement. To avoid padding, I merged implementation variants into their parents instead. Section 3 lists the 6 entries the gap hunt added (5 blurs, 1 contrast), and the candidates it considered and folded.
- **Where the detail lives.** This file is the index, the verdicts and the corrections. The full entry for every pre-existing id (definition, parameters, discrete kernel, frequency response, properties, algorithms, GPU, fingerprint, sources) stays in the researcher file and section named in the master table's last column. Gap entries (section 3) carry their full field set here.
- **Corrections override.** Where section 5 corrects a researcher file, the correction wins until the researcher file is updated.

## 1. Family taxonomy

Eleven blur families, plus one group for things that are not blurs. Each family answers one question a viewer could ask about a blur.

**Two notes on placement.**
1. `heat-equation` is mathematically identical to `gaussian-blur` (σ = √(2t)). It keeps its own id in F9 because "time is blur" is a lesson of its own, and because its explicit-iteration implementation is the reference for `perona-malik`. In the master table it is flagged as the same operator as `gaussian-blur`.
2. The generic "backdrop blur / frosted glass / glassmorphism" pipeline (NL B1) is not given an id. It is the **preamble of F10**: every F10 entry is an instance of NL B1's capture → downsample → blur → colour → composite skeleton. Figma's and Sketch's "background blur" are listed as aliases of `css-backdrop-filter`, the most precisely specified instance.

**Verdict vocabulary** (from NL §0, adopted for the whole catalog). TRUE BLUR: convex, low-pass, linear, shift-invariant, data-independent weights. ADAPTIVE BLUR: convex and low-pass but with data-dependent weights. RANK FILTER: output is an order statistic. BLUR IN EXPECTATION: each realization is a resampling; the average over realizations is a true blur. LINEAR SHIFT-VARIANT (LSV) BLUR: linear and convex but the PSF changes with position (motion fields, zoom, spin, depth of field, variable blur). COMPOSITE: a true blur plus colour or geometric stages. BLUR-DERIVED: uses a blur to build something else. NOT A BLUR: fails the convexity or low-pass test.

## 2. Master table

Column key.
- **LSI?** yes = one PSF and one MTF describe it completely. LSV = linear, shift-variant. NL = nonlinear (weights depend on the data). E = blur in expectation only. ≈ = approximately LSI (small shift variance from decimation or rounding).
- **Sep?** Can it run as a horizontal pass then a vertical pass with an identical result? yes / no / skew (separable along non-orthogonal axes) / approx (an approximation).
- **Cost class** (per output pixel). **O(1)**: independent of blur size (running sums, SAT, IIR, pyramids). **O(r)**: linear in radius (separable FIR, line gathers). **O(r²)**: 2-D gather. **O(log N)**: FFT. **O(S)**: S stochastic samples. **iter**: n iterations of a small stencil. **capture**: dominated by capturing the backdrop. **ALU**: arithmetic only.
- **Tier**: see section 6 (1 = full GPU + CPU reference + all layers + pixel trace; 2 = GPU with lighter layers; 3 = atlas and CPU-computed plots only; S = system implementation shown and measured live, our own model alongside).
- **Detail**: the file and section that hold the full entry. LSI = `catalog-lsi.md`, SPA = `catalog-spatial.md`, NL = `catalog-nonlinear.md`, CAT = this file.

## 3. Gap hunt: what was missing, and the added entries

**Method.** I walked the lists an imaging or graphics expert would check the catalog against: (a) every item in Photoshop's Filter > Blur menu and Blur Gallery; (b) every filter in Apple's `CICategoryBlur` plus MPS and vImage; (c) the edge-preserving canon of computational photography (Paris et al. 2009 survey, Gonzalez & Woods ch. 4–5); (d) the standard PDE/variational list (Weickert 1998); (e) game post-processing (bloom, DoF, motion blur, light shafts, SSS); (f) the WYSIWYG controls the brief names (SwiftUI, CSS, Figma). For each item not already covered I asked two questions: is it a distinct operator (not an implementation of an existing one), and would leaving it out make the catalog look incomplete to an expert?

**Coverage before the gap hunt.** Photoshop Blur menu: Average **missing**; Blur and Blur More (fixed small kernels, folded into `binomial-blur` as INFERRED "≈ 3×3" users, algorithm UNVERIFIED); Box, Gaussian, Lens, Motion, Radial, Smart, Surface present; Shape Blur **missing** (added as an alias of `fft-convolution`, since it is a convolution with a user-chosen kernel image). Blur Gallery: Field (= `variable-progressive-blur`), Iris (variant of `tilt-shift`), Tilt-Shift, Path, Spin present. Core Image `CICategoryBlur`: all covered, including morphology (contrast group) and `CIZoomBlur`; `CIAreaAverage` **missing** (now under `average-blur`). Variational/PDE: Perona–Malik present; **TV (ROF)** and **coherence-enhancing diffusion** missing. Game post: light shafts were only a sentence inside zoom blur; promoted. WYSIWYG: SwiftUI's own `.blur(radius:)` had measurements (CAL) but no catalog id; added. Inverse of blur: **deconvolution** missing; added to the contrast group, because "which blurs can be undone" is the cleanest way to show why MTF zeros matter.

**Considered and folded (not given ids).** Weighted least squares smoothing (Farbman, Fattal, Lischinski & Szeliski 2008, "Edge-preserving decompositions for multi-scale tone and detail manipulation", SIGGRAPH), L0 gradient smoothing (Xu, Lu, Xu & Jia 2011, SIGGRAPH Asia), rolling guidance filter (Zhang, Shen, Xu & Jia 2014, ECCV) and BM3D (Dabov et al. 2007): each is a further member of F8 whose teaching point (edge-aware smoothing, structure vs texture) the app already covers with `guided`, `domain-transform`, `tv-denoise` and `nonlocal-means`. They are good atlas footnotes, not new fingerprints. Screen-space subsurface scattering (Jimenez et al. 2009/2015) is a `sum-of-gaussians` (variant of `lorentzian-blur`) applied with depth-aware weights: listed as a user, not a new id. Mipmapping and anisotropic texture filtering (trilinear, EWA) are resampling filters, discussed under `pyramid-blur` (LOD bias) and `anisotropic-gaussian` (EWA footprints). Lateral chromatic aberration is a per-channel warp, not a blur. Temporal antialiasing is designed to avoid blur (SPA §1.7). Rolling shutter is a skew (SPA §1.5).

### 3.1 `average-blur` — Average (the infinite blur)

- **Aliases:** Photoshop *Filter > Blur > Average*; `CIAreaAverage` (returns a 1×1 image of the mean colour of a region); `CIAreaMaximum`'s averaging sibling; "average colour" used for adaptive UI tints; the top level of a mip chain. **Family:** F1. Verdict: TRUE BLUR (as a limit).
- **Definition.** g(x) = (1/|Ω|) ∫_Ω f(y) dy for every x in the region Ω. It is the limit of every normalized blur as its size grows: a Gaussian with periodic boundaries as σ → ∞, the heat equation with reflecting (Neumann) boundaries as t → ∞ (mass is conserved and the only steady state is the constant), a box as wide as the region. COMPUTED (standard consequence of normalization and mass conservation).
- **Parameters.** The region (selection or whole image). No size parameter: it is the end point of every size slider.
- **Discrete kernel.** h = 1/N on the region; the output is one value. Reference (REFERENCE, Adobe Photoshop help "Blur filters": Average finds the average colour of an image or selection and fills it with that colour; wording paraphrased, page not re-fetched in this pass. Apple Core Image Filter Reference, `CIAreaAverage`: returns a single-pixel image containing the average colour of the region of interest).
- **Frequency response.** H(0) = 1 and H(ν) = 0 for every ν ≠ 0 on the region's DFT grid: only DC survives. COMPUTED.
- **Properties.** Linear, normalized, positive, idempotent (unlike every finite blur), shift-invariant within a periodic region; the colour is computed in whatever space the pipeline blends in (the sRGB mean of black and white is 0.5 encoded, i.e. 0.214 linear; the linear mean is 0.5 linear, i.e. 0.735 encoded; CAL's "stripes 0.735" measurement is this effect).
- **Algorithms and cost.** One parallel reduction: O(N) work, O(log N) depth; on the GPU a `simd_sum` + threadgroup reduction or a mip chain to 1×1 (exact only for power-of-two sizes with a box mip filter); then one fill pass. MODELED.
- **Visual fingerprint.** Everything becomes one flat colour. On its own it is trivial; its use is as the end point of the σ slider and as the place where "blurring in sRGB vs linear light" gives the biggest, simplest difference (a black/white checkerboard averages to 0.5 encoded grey or 0.735 encoded grey).
- **Where used.** Photoshop Average; average-colour sampling for adaptive tints and luminance tracking (Liquid Glass's `averageColor` CAFilter and `tracksLuma` are INFERRED to do this, NL D3); auto-exposure metering.
- **Signature:** "The blur at infinity: one colour, the mean, and the cleanest demonstration of linear versus gamma averaging."
- **Tier 3** (trivial on the GPU; it earns its place in the atlas and as the end stop of every slider).

### 3.2 `tv-denoise` — Total-variation (ROF) smoothing

- **Aliases:** ROF model, TV regularization, TV denoising, TV-L2; TV-L1 (a variant with an L1 data term). **Family:** F8 (variational). Verdict: ADAPTIVE BLUR (edge-preserving smoother; its output is not a pointwise convex average, but it obeys a maximum principle).
- **Definition** (Rudin, Osher & Fatemi 1992, "Nonlinear total variation based noise removal algorithms", Physica D 60(1–4):259–268; REFERENCE, standard). u = argmin_u ∫|∇u| dx + (1/(2λ)) ∫(u − f)² dx. The first term charges edges by their **length times their height**, not by their steepness, so a sharp step costs the same as a smooth ramp of the same height and the minimizer has no reason to blur steps.
- **Parameters.** λ (in this form, intensity × pixels; larger λ = smoother). Like the bilateral's σr it sets a contrast scale, but it acts through geometry: a bright disc of radius R and height h on a flat background comes out as a disc of the **same radius** and height max(0, h − 2λ/R). Features are removed by size-to-contrast ratio, not by spatial frequency. REFERENCE (Meyer 2001, *Oscillating Patterns in Image Processing and Nonlinear Evolution Equations*, AMS University Lecture Series 22; Strong & Chan 2003, "Edge-preserving and scale-dependent properties of total variation regularization", Inverse Problems 19(6); both from memory, not re-read) and CHECKED numerically (`rof.py`, Chambolle's algorithm, 128×128, isotropic discrete TV): R = 16, λ = 4 → contrast 0.489 (predicted 0.50); R = 16, λ = 2 → 0.748 (0.75); R = 32, λ = 4 → 0.768 (0.75); R = 8, λ = 2 → 0.487 (0.50).
- **Discrete construction.** Forward-difference gradient, matching backward-difference divergence, isotropic |∇u| = sqrt(u_x² + u_y²) (anisotropic |u_x| + |u_y| gives square-cornered results). Chambolle's dual projection (Chambolle 2004, "An algorithm for total variation minimization and applications", J. Math. Imaging and Vision 20:89–97; REFERENCE): p ← (p + τ∇(div p − f/λ)) / (1 + τ|∇(div p − f/λ)|), τ ≤ 1/8, u = f − λ div p. Primal-dual (Chambolle & Pock 2011, J. Math. Imaging and Vision 40(1)) converges faster.
- **Frequency response.** None (nonlinear). Its amplitude-dependent transfer is the opposite of a low-pass: a large-amplitude, low-frequency sinusoid is attenuated by a fixed amount per unit of perimeter, so small-amplitude texture vanishes entirely while large steps keep their height (minus the 2λ/R-type loss). COMPUTED (from the disc law).
- **Properties.** Nonlinear, shift-invariant, rotation-invariant (isotropic TV), maximum principle (output in the input range), edge-preserving, **contrast loss** proportional to perimeter/area, **staircasing** on ramps (smooth slopes become terraces), corners rounded (a square loses its corners first). Not separable, not a semigroup. Convex problem, unique minimizer.
- **Algorithms and cost.** Iterative: each Chambolle iteration is a gradient, a divergence and a pointwise projection, about 8–10 fetches per pixel; 50–300 iterations for visual convergence (MODELED; the count depends on λ and the image). Perfectly parallel per pixel.
- **GPU implementation.** Ping-pong a 2-channel dual field p (RG32F) and the image; one compute dispatch per iteration; fusing several iterations per dispatch inside threadgroup tiles (as for diffusion, NL A12) cuts bandwidth. fp32 required.
- **Visual fingerprint.** Cartoon-flat regions with sharp edges; small low-contrast details vanish completely while large ones only dim; ramps become terraces; corners round off. Next to Perona–Malik: similar look, but TV's result is a well-posed minimizer (no time to choose, no backward diffusion, no surviving noise spikes). Best test: noisy piecewise-constant discs of several radii (shows the 2λ/R law), and a noisy ramp (staircasing).
- **Where used.** Medical and scientific denoising; regularizer in CT/MRI reconstruction, inpainting and optical flow (TV-L1 flow); deblurring priors. Consumer photo apps rarely name it (UNVERIFIED for specific products).
- **Signature:** "Pay for edges by their length, not their height: noise goes, steps stay, and small things fade by 2λ over their radius."
- **Tier 3.**

### 3.3 `coherence-enhancing-diffusion` — Coherence-enhancing (tensor) diffusion

- **Aliases:** CED, anisotropic tensor diffusion, edge-enhancing diffusion (EED, its sibling). **Family:** F9. Verdict: ADAPTIVE BLUR.
- **Definition** (Weickert 1999, "Coherence-enhancing diffusion filtering", International Journal of Computer Vision 31(2/3):111–127; Weickert 1998, *Anisotropic Diffusion in Image Processing*, Teubner; REFERENCE from memory, constants not re-read). ∂u/∂t = div(D(J_ρ) ∇u), where J_ρ = G_ρ * (∇u_σ ∇u_σᵀ) is the smoothed **structure tensor** (the same tensor `kuwahara-anisotropic` uses) with eigenvalues μ1 ≥ μ2 and eigenvectors (v1 across the local structure, v2 along it). D has the same eigenvectors with eigenvalues λ1 = α (tiny diffusion across) and λ2 = α + (1 − α)·exp(−C/(μ1 − μ2)²) along the flow when μ1 ≠ μ2 (λ2 = α otherwise). Typical α = 0.001. Unlike Perona–Malik's scalar conductivity, D is a **tensor**: diffusion strength depends on direction.
- **Parameters.** σ (noise scale for the gradient), ρ (integration scale: the size of the "flow" being followed), C (coherence threshold), α, stopping time t.
- **Discrete construction.** Per iteration: Gaussian-smoothed gradients, tensor components smoothed by G_ρ (3 separable Gaussian blurs), eigen-decomposition per pixel (closed form for 2×2), then a 9-point anisotropic stencil (the mixed term D12 u_xy needs diagonal neighbours). Explicit time step bounded for stability (about 0.15–0.25 depending on the stencil; UNVERIFIED exact bound); semi-implicit AOS schemes allow larger steps.
- **Frequency response.** None. Locally, it is a 1-D heat flow along v2: the local "PSF" is an elongated Gaussian aligned with the image's own flow, so it is the data-driven cousin of `anisotropic-gaussian` and `path-blur` (whose flow field is user-drawn). COMPUTED (reduction for a constant tensor).
- **Properties.** Nonlinear, shift- and rotation-invariant, mass-conserving (divergence form), maximum principle (for appropriate discretizations), not separable. Closes gaps in line-like structures and straightens interrupted flows; does not sharpen edges as Perona–Malik's backward regime does.
- **Algorithms and cost.** Each iteration ≈ 3 separable blurs (tensor smoothing) + 9 fetches; tens to hundreds of iterations. O(iterations × (σ + ρ)) per pixel. MODELED.
- **GPU implementation.** Compute passes: gradient → tensor → separable smoothing (reuse the app's Gaussian) → per-pixel diffusion tensor → stencil update. fp32 for long runs.
- **Visual fingerprint.** Brush-stroke flow along every oriented structure: fingerprint ridges become continuous, wood grain becomes clean lines, noise between ridges turns into streaks along the ridge direction. Best test: noisy concentric rings or a synthetic fingerprint (sum of oriented sinusoids) with gaps; compare with `perona-malik` (stops at edges but does not follow flow) and `path-blur` (follows a field the user drew).
- **Where used.** Fingerprint and seismic image enhancement; painterly flow filters (G'MIC "anisotropic smoothing" family, INFERRED).
- **Signature:** "Heat that flows along the grain and never across it: broken lines join and noise turns into strokes."
- **Tier 3.**

### 3.4 `swiftui-layer-blur` — SwiftUI `.blur(radius:opaque:)`

- **Aliases:** SwiftUI view blur, "layer blur" (the Figma term for blurring a layer's own content). **Family:** F10 (WYSIWYG anchor). Verdict: TRUE BLUR at small radii; approximately LSI above about 5 device pixels.
- **What Apple documents** (REFERENCE, Apple Developer Documentation `View.blur(radius:opaque:)`, quoted in CAL §5.1): it "Applies a Gaussian blur to this view"; `radius` is "the radial size of the blur"; `opaque` controls whether the blur output may be transparent. Nothing about σ, colour space or borders.
- **What it measurably does** (MEASURED on macOS 27.2 through `ImageRenderer.cgImage`, CAL §4.0 and §5.1; iOS not yet measured): radius is in points; σ ≈ 1.00·r·scale while r·scale ≤ 5 device px (a sampled Gaussian), and σ ≈ 0.90·r·scale above (a separable, box³-like kernel with excess kurtosis −0.45, compact at 3.55σ, and slightly shift-variant: the blurred edge's centre wobbles up to 1.2–1.4 px with grid phase, which indicates resampling). It blends gamma-encoded values in the default `.nonLinear` colour mode and linear light in `.linear`/`.extendedLinear`. With `opaque: false` it fades to transparent and spills past the frame; with `opaque: true` it clamps (r ≤ 4) or does something that is not a plain clamp (r ≥ 8). A second path, `ImageRenderer.render(rasterizationScale:)`, gives σ = 0.98·r with a near-Gaussian kernel: the same view differs by 9% in σ between the two render paths (MEASURED).
- **Parameters and conversions.** On an iPhone 15 Pro Max (scale 3) the regime switch is at r ≈ 1.8 pt and the large-r law predicts σ ≈ 2.7·r device px (INFERRED from the Mac law; must be re-MEASURED on the device with `measurePSF`, CAL §7).
- **Frequency response.** Gaussian below the switch; above it, close to a three-box product of sincs (≈ 1% contrast inversion, see `iterated-box`), plus aliasing from the internal resampling (no exact single MTF). COMPUTED from the measured shape.
- **Internals.** INFERRED: a downsample-blur-upsample (pyramid or fractional resampling) path with box-like passes above 5 px; render-server details are invisible to the app.
- **What the app does.** Shows the system result live (badge LIVE), fits σ, kurtosis and edge wobble on device (MEASURED), and places our own Gaussian and three-box implementations beside it at the fitted σ so the user can see which one SwiftUI resembles at each radius. This is the clearest "WYSIWYG → measured → modeled" chain in the app.
- **Visual fingerprint.** At small radii indistinguishable from a Gaussian; at larger radii a very slightly squarish, firmer-edged glow on point lights and a sub-pixel wobble when the content moves; gamma-space darkening of bright-on-dark detail by default.
- **Where used.** Every SwiftUI app that calls `.blur`. (Backdrop materials are a different effect: `apple-uiblureffect`.)
- **Signature:** "Apple says Gaussian; the pixels say Gaussian until five device pixels, then a quicker three-box look-alike at 0.9 of the radius."
- **Tier S** (system implementation, measured live) with Tier 1 models (`gaussian-blur`, `iterated-box`) beside it.

### 3.5 `god-rays` — Light shafts (volumetric light scattering as a post-process)

- **Aliases:** god rays, crepuscular rays, sun shafts, light shafts, radial light scattering. **Family:** F11. Verdict: BLUR-DERIVED.
- **Definition** (Mitchell, "Volumetric Light Scattering as a Post-Process", GPU Gems 3 ch. 13, 2007; REFERENCE, page read in this pass; the equation is printed as an image, so this form is reconstructed from the text and Listing 13-1): with uv the pixel, uv_L the light's screen position and C an occlusion image (the light source drawn bright, occluders black), Δ = density·(uv − uv_L)/N and
  out(uv) = exposure · [ C(uv) + Σ_{i=1..N} weight · decay^(i−1) · C(uv − iΔ) ].
  It is `radial-zoom-blur` (gather toward a centre, streak length proportional to distance) with **exponentially decaying** weights instead of a box, applied to a mask and **added** to the frame. The decay makes the radial PSF a one-sided exponential comet, the radial analogue of `kawase-streak`.
- **Parameters.** N (samples), density (step length as a fraction of the distance to the light; the article's text and code disagree on its direction of effect, so measure it), weight, decay ∈ [0, 1], exposure; light position; the occlusion mask.
- **Discrete kernel.** N bilinear taps along the ray toward the light; weights weight·decay^(i−1) (not normalized; exposure rescales). Sampling condition as for zoom blur: tap spacing at the far pixels must be ≤ ~1 px or the rays band; implementations render at reduced resolution and accept or dither the banding.
- **Frequency response.** None globally (LSV). Locally along each ray: a one-sided exponential, |H| never zero, non-zero phase (energy is pushed away from the light). COMPUTED (as SPA §1.3).
- **Properties.** Linear in the mask for fixed parameters; LSV; not normalized (adds light); the occlusion mask makes the whole effect depend nonlinearly on the scene.
- **Cost.** N fetches per pixel at the effect's resolution (often 1/4 to 1/2 linear resolution), plus a mask pass and an additive composite. MODELED.
- **Visual fingerprint.** Bright rays fanning out from a light partly hidden by occluders (leaves, window bars, clouds); rays shorten as the light moves behind more occluders; banding when N is low. Unlike bloom, the rays are radial and shaped by what blocks the light.
- **Where used.** Mitchell 2007; most real-time engines' light-shaft or sun-shaft effects (lineage per engine UNVERIFIED).
- **Signature:** "A zoom blur of the occluders toward the sun, with weights that fade like scattered light."
- **Tier 2.**

### 4.1 `wiener-deconvolution` — Deconvolution (Wiener, Richardson–Lucy)

- **Aliases:** inverse filter, Wiener filter, regularized deconvolution, Richardson–Lucy (RL), "deblur", "Shake Reduction" (Photoshop estimates a camera-shake kernel and deconvolves; algorithm not public). **Group:** contrast. Verdict: NOT A BLUR (the inverse of one).
- **Definition.** For an observed image b = h * f + n with known PSF h: the naive inverse F̂ = B/H fails wherever H ≈ 0. The Wiener filter (Wiener 1949, *Extrapolation, Interpolation, and Smoothing of Stationary Time Series*, MIT Press; REFERENCE, standard) uses W(ν) = H*(ν) / (|H(ν)|² + K(ν)), with K the noise-to-signal power ratio (a constant in the simplest form). Richardson–Lucy (Richardson 1972, "Bayesian-based iterative method of image restoration", JOSA 62(1):55–59; Lucy 1974, "An iterative technique for the rectification of observed distributions", Astronomical Journal 79(6):745; REFERENCE, standard) iterates u ← u · (h̃ * (b / (h * u))), with h̃ the flipped PSF: a multiplicative, positivity-preserving maximum-likelihood update for Poisson noise.
- **Parameters.** The PSF (from any blur in this catalog), K (Wiener) or the iteration count (RL).
- **Frequency response.** Wiener: W(ν) ≈ 1/H(ν) where |H|² ≫ K, and → 0 where H → 0. COMPUTED consequences for this catalog: (1) **box and disc blurs are not invertible** at their MTF zeros (box: ν = k/w; disc: ρ = 0.6098/R, 1.1166/R, …); the information there is gone, and the restored image shows ringing at exactly those frequencies. (2) The **Gaussian has no zeros but tiny values**: for σ = 1, H = 0.291 at ν = 0.25 (inverse gain 3.4) and 0.0072 at Nyquist (inverse gain 139), so noise at high frequencies explodes; for σ = 2, H(0.5) = 2.7·10⁻⁹. (3) A **coded (flutter) shutter** keeps |H| ≥ 0.036 everywhere (SPA §1.5), which is why it makes motion deblurring well-posed. (4) `binomial-blur` zeroes Nyquist exactly, so a binomial-blurred checkerboard cannot be recovered.
- **Properties.** Wiener: linear, shift-invariant, not positive (rings). RL: nonlinear, keeps positivity, converges slowly, amplifies noise if run too long.
- **Algorithms and cost.** Wiener: one FFT forward, one complex multiply, one inverse: O(log N) per pixel (reuse `fft-convolution`). RL: two convolutions per iteration, tens of iterations.
- **GPU implementation.** Through the same FFT path as `fft-convolution` (MPSGraph FFT on the GPU, vDSP in `BlurCore`); RL as ping-pong passes reusing any blur kernel.
- **Visual fingerprint.** Blurred text snaps back to legible, with ringing halos at the frequencies the blur zeroed and amplified grain where the blur was strong; with K too small, noise dominates; with K too large, it stays blurry. Best test: text blurred by box, disc and Gaussian at equal σ, plus a small amount of noise, then deconvolved: the Gaussian recovers best at low noise, the box and disc leave patterned ringing at their zero rings.
- **Where used.** Astronomy and microscopy; Photoshop Shake Reduction (kernel estimation + deconvolution; internals UNVERIFIED); scientific image restoration.
- **Signature:** "Divide by the blur's spectrum: whatever the blur sent to zero is gone for good, and whatever it nearly zeroed comes back as noise."
- **Tier 2** (CPU vDSP reference; GPU via the FFT path).

## 6. Tiers for the app

### 6.1 Rules for the cut

A blur earns **Tier 1** (full Metal implementation, CPU reference in `BlurCore`, all layers from WYSIWYG to pixels, and a pixel trace) when all of these hold:
1. **Distinct fingerprint.** It shows something no other Tier 1 entry shows (a PSF shape, an MTF feature, a cost class, or a failure mode).
2. **Traceable.** One output pixel can be followed through a small, finite set of input pixels and weights. Gathers, separable passes, recursions, pyramids and short iterations qualify. FFT-based and global methods do not (every output pixel depends on every input pixel, so the "trace" is a spectrum, not a footprint).
3. **Self-contained input.** It runs on the procedural test images alone. Entries that need extra buffers (velocity, depth, guide images) or a sequence of frames are Tier 2 at most.
4. **Exact CPU reference is feasible**, so GPU↔CPU parity can be tested on the Mac (BRIEF engineering shape).
5. **Teaches a pair** in section 7 against another Tier 1 entry.

**Tier 2** entries get a Metal implementation and a CPU reference, but lighter layer content (no per-tap pixel trace, or a trace of one stage only): they need extra inputs, are composites, are FFT-based, or mostly repeat a Tier 1 lesson with a new twist. **Tier 3** entries live in the atlas with math, PSF and MTF plots computed on the CPU (or shown through an Apple system implementation), because they are slow iterative methods, platform materials we cannot run, or limits and footnotes. **Tier S** marks Apple system implementations that the app runs live and measures (LIVE/MEASURED badges), always next to our own modeled reimplementation.

The table has 27 rows: 23 catalog entries plus 4 implementation variants (`sat-box`, `stack-blur`, `gaussian-separable`, `gaussian-linear-sampling`). The heat equation rides along inside row 26 as the explicit-diffusion variant of the Gaussian. The target was 20–28 blurs; the cut lands at **23 entries / 27 kernels**. The contrast entry `unsharp-mask` is also built at Tier 1 quality because it is one fused pass over the Tier 1 Gaussian and is the clearest "what blur enables" demo.

**Why these and not others (the cut).**
- **Kept over FFT-based entries** (`fft-convolution`, `frequency-lowpass`, `lorentzian-blur`, `diffraction-airy`): no per-pixel trace, and the MPSGraph FFT path is one engineering investment that serves all four, so they share Tier 2.
- **`exponential-blur` over `lorentzian-blur`:** both show heavy tails; the exponential does it exactly in O(1) with a traceable recursion.
- **`anisotropic-gaussian` over `kawase-streak`:** it completes the box-vs-Gaussian lesson along a line and is Core Image's actual motion blur; streaks need thresholding and repeat Kawase's doubling idea.
- **`spin-blur` and `radial-zoom-blur` over `path-blur`:** they are exact, have closed-form polar/log-polar math and are perfect duals; path blur needs a user-drawn vector field (Tier 2).
- **`polygonal-bokeh` over `circular-separable-bokeh` and `stochastic-bokeh`:** both disc variants are kept at Tier 2 as algorithm toggles on `disc-blur`; the hexagon teaches a new mathematical idea (Minkowski sums and zonogons).
- **`depth-of-field-coc`, `velocity-buffer-motion-blur`, `joint-bilateral`, `temporal-accumulation`:** need depth, velocity, guide images or frame sequences (rule 3). They are Tier 2 with procedural scenes that carry those buffers.
- **`bilateral` brute force over the grid and separable variants:** the brute-force version has the exact weight map for the probe-pixel PSF overlay; the grid and separable versions are Tier 2 toggles that show their artifacts against it.
- **`kuwahara` classic over anisotropic:** the anisotropic version needs a structure-tensor pipeline (several passes) and ~340 fetches per pixel; Tier 2.
- **`nonlocal-means`, `mean-shift`, `tv-denoise`, `coherence-enhancing-diffusion`:** heavy iterative or search-based methods whose lesson ("patches, modes, variational, tensor") is better shown on a small CPU-computed crop. NLM gets a GPU preview at Tier 2 because it is the best denoiser demo.
- **UI materials:** Apple's are system implementations (Tier S, measured) with our own model at Tier 2; Windows and Android materials cannot be run on iOS, so they are Tier 3 models.
